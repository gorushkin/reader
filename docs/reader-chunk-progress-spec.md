# ТЗ: вычисление и синхронизация позиции чтения внутри чанка

## 1. Цель

Реализовать простой механизм определения позиции пользователя внутри чанка книги.

Позиция используется для:

- сохранения прогресса чтения;
- восстановления места чтения;
- синхронизации между устройствами;
- перехода к приблизительно тому же месту после изменения размеров экрана или настроек отображения.

Позиция не должна храниться в виде номера страницы, поскольку количество страниц зависит от ширины экрана, размера шрифта и других параметров отображения.

---

## 2. Основной принцип

Контент чанка рендерится в горизонтальные CSS-колонки.

Каждая колонка соответствует одной отображаемой странице.

После рендера определяется общее количество страниц чанка:

```ts
const pageCount = Math.ceil(content.scrollWidth / viewportWidth)
```

Индекс страницы начинается с нуля:

```text
0 — первая страница
1 — вторая страница
2 — третья страница
...
```

Позиция пользователя внутри чанка хранится в процентах от `0` до значения меньше `100`.

---

## 3. Вес одной страницы

Вес одной страницы в прогрессе чанка вычисляется по формуле:

```ts
const chunkColumnWeight = 100 / pageCount
```

Например, если контент чанка занимает восемь страниц:

```ts
pageCount = 8
chunkColumnWeight = 100 / 8 // 12.5
```

Каждая перевёрнутая страница увеличивает прогресс чанка на `12.5`.

---

## 4. Вычисление прогресса

Прогресс внутри чанка вычисляется по формуле:

```ts
const chunkProgress = pageIndex * chunkColumnWeight
```

То же самое без промежуточного значения:

```ts
const chunkProgress = (pageIndex / pageCount) * 100
```

Пример для чанка из восьми страниц:

| Индекс страницы | Отображаемая страница | Прогресс |
|---:|---:|---:|
| `0` | 1 | `0%` |
| `1` | 2 | `12.5%` |
| `2` | 3 | `25%` |
| `3` | 4 | `37.5%` |
| `4` | 5 | `50%` |
| `5` | 6 | `62.5%` |
| `6` | 7 | `75%` |
| `7` | 8 | `87.5%` |

Таким образом, когда отображается первая страница, прогресс равен `0%`.

Прогресс увеличивается только после перехода на следующую страницу.

Последняя отображаемая страница не соответствует `100%`, поскольку значение прогресса обозначает начало текущей страницы.

Значение `100%` означает, что чанк полностью пройден и читатель должен перейти к следующему чанку.

---

## 5. Модель позиции

Для сохранения позиции используется следующая структура:

```ts
type ReadingPosition = {
  chunkId: string
  chunkProgress: number
}
```

Пример:

```ts
const position: ReadingPosition = {
  chunkId: 'chapter-12',
  chunkProgress: 37.5,
}
```

Эта позиция означает, что пользователь находится приблизительно на отметке `37.5%` внутри чанка.

Дополнительно локальное состояние Reader Engine может хранить текущий индекс страницы:

```ts
type ReaderState = {
  chunkId: string
  pageIndex: number
  pageCount: number
  chunkProgress: number
}
```

`pageIndex` и `pageCount` являются производными от текущей пагинации и не должны использоваться как основная синхронизируемая позиция.

---

## 6. Момент обновления прогресса

Прогресс обновляется после успешного переключения страницы.

При переходе вперёд:

```ts
pageIndex += 1
chunkProgress = pageIndex * chunkColumnWeight
```

При переходе назад:

```ts
pageIndex -= 1
chunkProgress = pageIndex * chunkColumnWeight
```

Прогресс не должен обновляться:

- в начале жеста перелистывания;
- во время анимации;
- если жест был отменён;
- если переключение страницы не завершилось;
- при простом открытии панели управления;
- при повторном рендере текущей страницы.

Сохранение и синхронизация выполняются только после того, как новая страница стала текущей.

---

## 7. Восстановление позиции

После загрузки чанка он заново разбивается на страницы под текущее устройство.

Количество страниц при восстановлении может отличаться от количества страниц на устройстве, на котором позиция была сохранена.

Индекс страницы вычисляется из сохранённого прогресса:

```ts
const pageIndex = Math.floor((chunkProgress / 100) * pageCount)
```

Эквивалентная формула:

```ts
const pageIndex = Math.floor(chunkProgress / chunkColumnWeight)
```

Полученное значение необходимо ограничить допустимым диапазоном:

```ts
const normalizedPageIndex = Math.min(
  Math.max(pageIndex, 0),
  pageCount - 1,
)
```

Пример:

```ts
chunkProgress = 37.5
pageCount = 12

pageIndex = Math.floor((37.5 / 100) * 12)
// 4
```

На новом устройстве будет открыта страница с индексом `4`, то есть пятая отображаемая страница.

Восстановление является приблизительным. Точное совпадение текста между устройствами не гарантируется.

---

## 8. Завершение чанка

Пока пользователь находится на последней странице чанка, прогресс соответствует началу этой страницы:

```ts
chunkProgress = ((pageCount - 1) / pageCount) * 100
```

При попытке перейти вперёд с последней страницы:

1. текущий чанк считается завершённым;
2. для него может быть сохранён прогресс `100`;
3. загружается следующий чанк;
4. следующий чанк открывается с первой страницы;
5. его прогресс устанавливается в `0`.

Пример:

```ts
currentPosition = {
  chunkId: 'chunk-42',
  chunkProgress: 100,
}

nextPosition = {
  chunkId: 'chunk-43',
  chunkProgress: 0,
}
```

---

## 9. Обратный переход между чанками

При попытке перейти назад с первой страницы текущего чанка:

1. загружается предыдущий чанк;
2. выполняется его пагинация;
3. открывается последняя страница предыдущего чанка.

Индекс вычисляется так:

```ts
const pageIndex = pageCount - 1
```

Прогресс предыдущего чанка:

```ts
const chunkProgress = (pageIndex / pageCount) * 100
```

Значение `100%` для отображения последней страницы не используется, поскольку оно означает позицию после окончания чанка.

---

## 10. Точность значений

`chunkProgress` хранится как число с плавающей точкой.

Не следует сравнивать значения прогресса через строгое равенство, кроме специальных значений `0` и `100`.

Для отправки на сервер значение допускается округлять, например до четырёх знаков после запятой:

```ts
const serializedProgress =
  Math.round(chunkProgress * 10_000) / 10_000
```

Внутренние вычисления желательно выполнять без промежуточного округления.

---

## 11. Ограничения подхода

Механизм обеспечивает приблизительное восстановление позиции.

Позиция может немного сместиться после изменения:

- ширины или высоты области чтения;
- размера и семейства шрифта;
- межстрочного интервала;
- отступов;
- оформления заголовков;
- содержимого чанка;
- алгоритма пагинации.

На первом этапе такое поведение считается допустимым.

Точное позиционирование по символам, блокам или DOM-узлам в текущую версию не входит.

---

## 12. Критерии приёмки

Механизм считается реализованным, если:

1. При открытии первой страницы чанка прогресс равен `0`.
2. Для чанка из восьми страниц вторая страница имеет прогресс `12.5`.
3. Для чанка из восьми страниц четвёртая страница имеет прогресс `37.5`.
4. Прогресс изменяется только после завершённого переключения страницы.
5. После изменения количества страниц сохранённый процент преобразуется в допустимый индекс страницы.
6. При достижении конца чанка сохраняется значение `100`.
7. Следующий чанк открывается с прогрессом `0`.
8. При переходе назад открывается последняя страница предыдущего чанка.
9. В синхронизируемой позиции не хранится номер страницы.
10. Точное позиционирование по структуре документа не требуется.

---

## Итог

Процент прогресса указывает на начало текущей страницы.

`100%` означает позицию после окончания чанка.

Основные формулы:

```ts
const chunkColumnWeight = 100 / pageCount
const chunkProgress = pageIndex * chunkColumnWeight
```
